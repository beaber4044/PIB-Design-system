## Repo-specific setup

- This repo ships as a Vite **app** (index.html + hashed asset build), not a library — there was no importable `dist/` entry exporting components before this sync.
- Added a separate library build so the converter has something to point `--entry` at:
  - `vite.lib.config.ts` — library-mode Vite config (kept separate from `vite.config.ts`, which stays the app/dev config).
  - `src/lib-entry.ts` — re-exports `./components` and side-effect-imports `./index.css`, so Tailwind (`@tailwindcss/vite`) compiles real utility CSS during the lib build (it scans every module Vite touches, so importing all 32 components pulls in every class they use). Without this import, `dist/design-system.css` would be empty.
  - `tsconfig.lib.json` — separate `tsc` config for declaration-only emit (`src/components`, `src/lib` → `dist/types/`). `tsconfig.app.json` has `noEmit: true` so it can't be reused directly.
  - `package.json` — added `build:lib` script, `module`/`types` fields.
- Build command: `npm run build:lib` (runs `tsc -p tsconfig.lib.json` then `vite build --config vite.lib.config.ts`). Outputs: `dist/index.es.js` (JS, react/react-dom external), `dist/design-system.css` (compiled Tailwind CSS), `dist/types/**` (declarations).
- `react`, `react-dom`, `react/jsx-runtime` are externalized in the lib build; `@tabler/icons-react` and `clsx` are bundled into `index.es.js` (regular dependencies, not externalized) — no `extraEntries` needed for icons.
- No Storybook, no `docs/` directory — component docs will be synthesized from `.d.ts` + JSDoc + authored previews.
- `cfg.tokensGlob`/`cfg.tokensPkg` only work when tokens ship inside an npm package under `node_modules` (`lib/css.mjs`'s `copyTokens` returns early when `tokensPkg` is unset, and `tokensGlob` is only consulted *inside* that package dir). This repo's `tokens/*.json` are plain repo-root files, not an npm package — the converter does NOT copy them. **Manual step after every `package-build.mjs` run**: `cp tokens/*.json ds-bundle/tokens/` before validating/uploading. (The actual rendering tokens — CSS custom properties — already ship correctly via `dist/design-system.css`; these JSON files are the supplementary Figma-style token source, `app.tokens.json` for native + `web.tokens.json` presumably for web, and are nice-to-have context for the design agent, not render-critical.)
- Font: `--font-sans` names `"Naver Sans"` first, which has no public standalone webfont distribution found. Shipped `NanumSquare` instead (next name in the same font-stack, confirmed open source — NAVER's own Nanum family, SIL OFL license) via `cfg.extraFonts: ["src/fonts/nanumsquare/index.css"]`, sourced from the official `@noonnu/nanumsquare` npm package (NAVER's font distribution platform) through jsDelivr. Files + `LICENSE.txt` live at `src/fonts/nanumsquare/`. `[FONT_MISSING]` still fires for the literal "Naver Sans" name (expected/accepted — non-blocking) since browsers fall through to NanumSquare in the stack regardless.

- **Tooltip**: bubble is `opacity-0` by default, only revealed via `group-hover:opacity-100` (pure CSS, no JS state) — a static capture can never show it open. The authored preview (`Triggers` cell) shows realistic trigger elements with an authored caption describing the hover content instead, and is graded on the trigger composition only. This is a permanent limitation of static capture, not a bug — don't try to force it with invented utility classes (the bundle only ships CSS for classes actually used in `src/`, so a new class on the preview has no compiled rule behind it).

- **Grid overflow overrides**: `cfg.overrides` sets `cardMode: "column"` for StatCard, Tooltip, AppBar, AppMainHeader, BottomNavigation, and Header (all render wider than a standard grid cell), and `cardMode: "single", viewport: "360x400"` for Modal (a `position:fixed` full-screen overlay). If a future re-sync's validate flags NEW `[GRID_OVERFLOW]` warnings on other components, add the same kind of override — see the base skill's `[GRID_OVERFLOW]` row.
- **Server-side font enrichment**: after the first upload + self-check, the claude.ai/design project's `fonts/` directory accumulated extra files (`.otf`, `.ttf`, "_ac" variants of NanumSquare) that this sync never uploaded — these appear to be the app's own font-completion step (recognizing the "NanumSquare" family and fetching sibling formats), same mechanism that generates `_ds_manifest.json`/`_adherence.oxlintrc.json`. Do NOT delete these on a future reconciliation pass just because the local `ds-bundle/fonts/` doesn't contain them — only reconcile-delete files whose absence you're sure means "this sync stopped producing it," not everything under `fonts/`.
- **No git repo**: this repo has no `.git` — nothing from this sync (config, NOTES, conventions, previews) has been committed anywhere. If the user later `git init`s this repo, the `.gitignore` entries are already in place; commit the durable set (`config.json`, `NOTES.md`, `conventions.md`, `previews/`) at that point.
