## Repo-specific setup

- This repo ships as a Vite **app** (index.html + hashed asset build), not a library — there was no importable `dist/` entry exporting components before this sync.
- Added a separate library build so the converter has something to point `--entry` at:
  - `vite.lib.config.ts` — library-mode Vite config (kept separate from `vite.config.ts`, which stays the app/dev config).
  - `src/lib-entry.ts` — re-exports `./components` and side-effect-imports `./index.css`, so Tailwind (`@tailwindcss/vite`) compiles real utility CSS during the lib build (it scans every module Vite touches, so importing all 32 components pulls in every class they use). Without this import, `dist/design-system.css` would be empty.
  - `tsconfig.lib.json` — separate `tsc` config for declaration-only emit (`src/components`, `src/lib` → `dist/types/`). `tsconfig.app.json` has `noEmit: true` so it can't be reused directly.
  - `package.json` — added `build:lib` script, `module`/`types` fields.
- Build command: `npm run build:lib` (runs `tsc -p tsconfig.lib.json` then `vite build --config vite.lib.config.ts`). Outputs: `dist/index.es.js` (JS, react/react-dom external), `dist/design-system.css` (compiled Tailwind CSS), `dist/types/**` (declarations).
- `react`, `react-dom`, `react/jsx-runtime` are externalized in the lib build; `@tabler/icons-react` and `clsx` are bundled into `index.es.js` (regular dependencies, not externalized) — no `extraEntries` needed for icons.
- No Storybook, no `docs/` directory — component docs will be synthesized from `.d.ts` + JSDoc + authored previews.
- `cfg.tokensGlob`/`cfg.tokensPkg` only work when tokens ship inside an npm package under `node_modules` (`lib/css.mjs`'s `copyTokens` returns early when `tokensPkg` is unset, and `tokensGlob` is only consulted *inside* that package dir). This repo's `tokens/*.json` are plain repo-root files, not an npm package — the converter does NOT copy them. **Manual step after every `package-build.mjs` run**: `cp tokens/*.json ds-bundle/tokens/` before validating/uploading. (The actual rendering tokens — CSS custom properties — already ship correctly via `dist/design-system.css`; these JSON files are the supplementary Figma-style token source, `app.tokens.json` for native + `web.tokens.json` presumably for web, and are nice-to-have context for the design agent, not render-critical.)
